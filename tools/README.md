# tools/ · 工程脚本

这些脚本**不参与系统运行**，只服务于开发者自己的迭代流程：把「改完代码 → 自查敏感项 → 对外发布」这条链路上容易遗漏、也容易出错的环节固化下来，让每次发布都可复现。

所有脚本**零第三方依赖**（Python 3 标准库），克隆后可直接运行，无需 `npm install`。

> 与 `tests/` 的分工：`tests/` 管功能回归，`tools/` 管发布前的自查。

## 脚本一览

| 脚本 | 解决什么问题 | 用法 |
| --- | --- | --- |
| `scan_repo.py` | 口令 / 模型 Key / 本机绝对路径一旦写进文档或提交历史，泄露不可逆 | `python scan_repo.py <待检目录> [--git-status]` |

## 核心设计：用断言代替记忆

- `scan_repo.py` 命中任意敏感模式（模型 Key、口令赋值、本机盘符路径、用户名残留）即退出码 1，
  可直接当 CI 门禁用；
- 它自动跳过 `.git`（含历史提交里的旧 blob）与 `node_modules`（第三方代码遍地是
  `123456789` 这类字符串，不剪枝会淹没真正的问题）；
- 除已知弱口令外，还会对「口令位被赋了非占位值」单独告警——**强口令推到公开仓库一样是泄露**，
  这类只能靠人工确认；
- `scan_repo.py` 只放行「启动树洞信箱.bat」里的两个本地演示口令（`admin2026` / `counselor2026`），
  同样的值若出现在别的文件里会被判定为疑似真实凭据并阻断。

## 发布前自查

```bash
# 把整个仓库（或待发布副本）喂给它，命中断言即退出码 1
python tools/scan_repo.py . --git-status
```

典型误报与排除：

- `http://`、`registry.npmmirror.com`、SVG 命名空间不是本机路径，脚本已按盘符 + 关键词剪枝；
- 文档里 `sk-你的DeepSeekKey` 这类**占位写法**不算 Key，只有「`sk-` 后接 16 位以上随机串」才判定为真 Key；
- `%LOCALAPPDATA%` 是 Windows 标准环境变量，可移植，不计入本机路径命中。

> 本目录只放**不需要任何凭据**的脚本。凡涉及真实口令与生产凭据的操作，请以环境变量传入，切勿写回脚本或提交入库。
