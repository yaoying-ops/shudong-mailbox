# 树洞语料脱敏流水线设计

> 适用对象：约 1 万组真实学生倾诉对话（纯文本 / JSON，已初步脱敏）
> 设计目标：把这批语料变成 **可安全分析、可长期留存、可跨批次复用** 的研究资产
> 参考实现：`deidentify.py`（已用合成语料跑通，60 条 → 全部标识符命中）

---

## 0. 四条不可动摇的原则

| 原则 | 含义 | 落地要求 |
|---|---|---|
| **原始不可改** | 只读输入，只写独立 output 目录 | 输入文件设只读；输出与原始物理隔离 |
| **可复现** | 同一 salt + 同一输入 → 同一输出 | salt 由环境变量统一管理，跨批次不变 |
| **可审计** | 每个类别替换了几次、抽样明细全部留痕 | 产出 `audit.json`，且审计文件本身不含原始 PII |
| **最小依赖** | 核心仅用标准库即可运行 | NER / 聚类等重型能力作为**可选增强**，缺失自动降级 |

> 为什么"最小依赖"是原则而不是偏好：脱敏是**数据入口的闸门**，闸门不能因为某个包装不上就放行。核心必须随时能跑。

## 1. 数据假设（先对齐 schema）

```json
[
  {
    "id": "u0001",
    "conversation": [
      {"role": "user",      "text": "老师，我叫李明，今年20岁，在南通大学读书……"},
      {"role": "assistant", "text": "我在，你愿意多说一点吗？"}
    ],
    "metadata": {
      "name": "李明", "student_id": "2021012345",
      "school": "南通大学", "grade": "大三", "major": "计算机", "gender": "男"
    }
  }
]
```

- **对话体**优先识别 `conversation / messages / dialog / turns` 等键；纯文本字段 `text / content / message` 兜底。
- 兼容 JSON 数组与 JSONL 两种格式，**输出格式与输入一致**，避免下游脚本返工。
- 若你的真实 schema 不同，只需改配置区的键名映射，不动核心逻辑。

## 2. 流水线总览（5 个阶段 + 1 个闸门）

```
 ┌─────────────┐   ┌──────────┐   ┌──────────────────────────┐   ┌────────┐   ┌──────────────┐
 │ S0 授权闸门 │──▶│ S1 载入  │──▶│ S2 脱敏层（顺序敏感）    │──▶│ S3 假 │──▶│ S4 审计/抽检 │
 │ 合规/同意   │   │ 校验/统计│   │ 正则→机构→日期→年龄→地名 │   │ 名化  │   │ S5 安全存储  │
 └─────────────┘   └──────────┘   └──────────────────────────┘   └────────┘   └──────────────┘
       │
       └─ 不通过则整批退回，不进入任何后续处理
```

### S0 · 授权与合规闸门（**不过则全停**）
- 语料来源必须有**知情同意**或合规匿名采集依据；心理类数据属敏感个人信息。
- 检查项：采集说明、同意范围（是否允许二次分析）、是否含未成年人（需额外保护）。
- **拒绝条件**：无法说明来源与授权 → 不处理，原件退回。

### S1 · 载入与校验
- 统计记录数、字段完整率、编码、异常记录（空对话、超长、乱码）。
- 输出一份 data profile，供后续分析对齐口径。

### S2 · 脱敏层（核心，见第 3 节）
五步固定顺序，**顺序错了会误伤或漏检**。

### S3 · 假名化
- 对姓名等需要"保留共指关系"的实体，用 **salt 哈希** 映射为稳定短 token（如 `<NAME_c35fab>`）。
- 同一批语料中"李明"始终映射为同一个 token → 分析时还能追踪"同一个人说了什么"，但**不可逆推**。

### S4 · 审计与抽检
- 产出 `audit.json`：各类别替换计数 + 遮蔽样本 + 高 PII 密度记录清单。
- 人工抽检（见第 6 节）。

### S5 · 安全存储与分级
- 脱敏语料、审计文件、原始语料**三者分目录、分权限**。
- 原始语料不出本地 / 不进版本库；脱敏语料可进分析环境。

## 3. 脱敏层详解

### 3.1 规则正则（直接标识符 → 占位符，不可逆）

| 类别 | 模式要点 | 替换 | 备注 |
|---|---|---|---|
| 手机号 | `1[3-9]` + 9 位，允许 `+86` 前缀 | `<PHONE>` | 特异性最高，**必须最先跑** |
| 身份证 | 17 位 + 校验位 / 15 位 | `<IDCARD>` | 与手机号/银行卡长度重叠，靠顺序消歧 |
| 邮箱 | 标准邮箱 | `<EMAIL>` | |
| 银行卡 | 15–19 位数字串 | `<BANKCARD>` | 兜底（前述已替换的不含数字，天然不冲突） |
| URL / IP | http(s)、www、IPv4 | `<URL>` `<IP>` | |
| 微信号 | `微信/微信号/vx/V信` + 可选"是/为/号" + ID | `<WECHAT>` | **必须容忍"微信是 xxx"这种口语写法** |
| QQ 号 | `QQ/扣扣` + 数字 | `<QQ>` | 裸数字不脱（易误伤年份/金额），需要时单独开启 |
| 学号/工号 | `学号/工号` + 数字 | `<STUDENT_ID>` | |

### 3.2 泛化（准标识符 → 降精度，保留分析价值）

| 类型 | 原样 | 泛化后 | 理由 |
|---|---|---|---|
| 日期 | `2021年3月15日` | `2021年3月` | 抹掉"日"，保留年月做时间趋势 |
| 年龄 | `20岁` | `20-24岁` | 5 岁分桶，降低唯一性 |
| 地址 | `江苏省南通市崇川区` | `江苏省` | 保留到省，抹掉市县 |
| 市级 | `南通`（无省份前缀时） | `江苏省` | 已出现省份则直接删除市名，避免"江苏省江苏省" |
| 年级/专业/性别 | `大三 / 计算机 / 男` | **保留** | 这三个是分析维度（见第 4 节），不该硬抹 |

### 3.3 机构名（需要"函数词守卫"）
- 朴素的做法会把 `在南通大学读书` 整段吞成占位符。
- 正确做法：匹配 `XX大学/学院/学校` 后，**剥掉开头的功能词**（在/了/的/是/去/上…），剩余 ≥2 字才替换。
- 结果：`在南通大学读书` → `在<SCHOOL>读书`。

### 3.4 中文姓名（最不确定的一环，分层处理）
1. **语境触发**（高精度）：`我叫/我是/名字叫/叫我` + 百家姓开头的 2–3 字 → 替换。
2. **可选 NER**（高召回）：jieba + 姓氏词典 + 常用名字，识别"姓+名"连续词。
3. 明确标注精度边界：启发式会有漏检（如"小张""阿明"）与少量误伤，**生产环境建议叠加一个中文 NER 模型**做交叉验证。

### 3.5 假名化
- `token = <PREFIX_ + sha256(salt || 实体)[:6]>`
- **salt 必须跨批次固定**，否则同一人在不同批次得到不同 token，共指关系断裂。
- 审计只存**遮蔽样本**（如 `13*****78`），防止审计文件本身成为泄露源。

## 4. 三类标识符要区别对待（关键设计）

| 类别 | 例子 | 处理策略 | 为什么 |
|---|---|---|---|
| **直接标识符** | 姓名、手机、身份证、学号、微信 | **抹除/占位符** | 单独即可定位到人 |
| **准标识符** | 年级、专业、性别、生源地、日期 | **泛化/分桶** | 组合起来可能唯一识别，但单独有分析价值 |
| **敏感内容** | 具体经历、他人姓名、机构 | **保留但评估** | 是分析对象本身，泛化过度会毁掉研究价值 |

> 设计取舍：**准标识符泛化而非抹除**。把"大三/计算机/男"都打成 `<GRADE>` 会让"人群差异分析"（分析阶段 7）直接失效——这是实测中踩到的坑。

---

## 5. 为什么"顺序"是硬约束

以 `我的手机138xxxx5678，学号2021012345` 为例：

- 若先跑银行卡（15–19 位）：可能把 11 位手机号 + 相邻数字连起来误伤。
- 若先跑学号再跑手机：学号规则命中后剩 `138xxxx5678`，仍能被手机规则正确捕获。

**固定顺序：手机号 → 身份证 → 邮箱 → 银行卡 → URL/IP → 微信号/QQ → 学号。**
替换后的占位符**不含数字**，天然阻断后续正则跨字段误匹配 —— 这是顺序能生效的底层保证。

## 6. 审计与质量抽检

### 6.1 `audit.json` 字段
```json
{
  "records": 60,
  "salt_fingerprint": "a1b2c3d4e5f6",
  "replacement_counts": {"phone": 19, "name_heuristic": 19, "school": 18, "date_generalized": 18},
  "samples_masked": {"phone": ["138*****78"]},
  "high_pii_density_records": ["s0003", "s0017"],
  "note": "审计文件同样只含遮蔽样本；请勿与原始语料同目录公开。"
}
```

### 6.2 人工抽检 SOP
| 项 | 做法 | 通过标准 |
|---|---|---|
| 抽样量 | 分层抽样 ≥ 200 条（含全部高危记录） | — |
| 检查项 | 是否残留真名/手机/校名/地址/可定位组合 | 直接标识残留 = **0** |
| 间接识别 | 年级+专业+性别+生源地组合是否仍唯一 | 每组 ≥ 5 人（k≥5） |
| 漏检 | 姓名启发式漏检率 | 抽检漏检 ≤ 2%，否则上 NER |
| 误伤 | 泛化是否破坏语义 | 关键信息仍可读 |

## 7. 风险与边界（必须写清楚）

1. **不可逆性**：占位符替换不可逆、salt 哈希不可逆；但**泛化（如只留到省）会损失信息**，不可恢复。
2. **间接识别仍可能存在**：极端个案描述（"我们学校唯一的航天专业"）即便脱敏也易被认出 → 需人工二次审查此类记录。
3. **误伤与漏检并存**：启发式姓名识别不完美，必须用抽检闭环。
4. **法律合规**：遵循《个人信息保护法》对敏感个人信息的处理要求；未成年语料需额外保护；留存最小必要、限期删除、访问留痕。
5. **禁止将审计文件与原始语料同时公开**。

## 8. 与树洞系统的对接点

| 脱敏产物 | 树洞侧的用途 |
|---|---|
| 脱敏语料 | 直接喂给分析流水线（见《分析方案》），或做 Agent few-shot 示例 |
| `audit.json` | 合规留痕、数据质量报告 |
| 高危记录清单 | **仅 id**，用于反向核对风险识别覆盖率（不回流原文） |

> 注意：脱敏语料**不回流到线上陪聊系统做实时处理**。线上仍应走独立的实时风控；这批语料只做离线研究，避免"研究数据泄露 → 影响真实用户"。

## 9. 运行方式（参考实现）

```bash
# 零依赖即可运行（姓名 NER、聚类等为可选增强）
python deidentify.py --input corpus.json  --outdir out --salt "$TREEHOLE_SALT"
python deidentify.py --input corpus.jsonl --outdir out
python deidentify.py --demo          # 合成数据自检
```

## 10. 已知局限与改进路线

| 局限 | 现状 | 改进方向 |
|---|---|---|
| 姓名启发式漏检 | 语境触发 + 姓氏词典 | 叠加中文 NER（如通用信息抽取模型）做交叉验证 |
| 地名词典不全 | 内置常用省 + 部分地级市 | 替换为全量行政区划表 |
| 无 k-匿名校验 | 仅泛化 | 增加"准标识符组合唯一性"检测 |
| 无审核界面 | 命令行 | 加一个 Web 复核台：并排显示原/脱敏 + 逐条确认 |
